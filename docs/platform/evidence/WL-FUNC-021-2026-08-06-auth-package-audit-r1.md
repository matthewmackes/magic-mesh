# WL-FUNC-021 — Music Ed25519 credential package-readiness audit (2026-08-06)

Status: the workstation RPM statically carries the provisioning path and its
enablement wiring, but installed-seat provisioning and authorized mutation
acceptance remain unproved. This audit performed no RPM install, reboot,
service restart, credential provisioning, or Dell runtime action.

## Scope and verdict

The audit covered the current-tree `magic-mesh-12.1.6-4` base RPM, the source
RPM manifests, the Music provisioning helper, the three relevant systemd
artifacts, and the existing RPM/secret self-tests. The base package is
payload-complete for the declared Music assets. The lighthouse package
correctly contains none of the workstation-only Music shell/daemon assets.

That is not yet an installed-seat proof: the package has not been installed
into a clean target, the helper has not run its production branch, and no
running `mde-musicd` has verified a public key generated by the packaged
helper.

The provisioning unit has `Before=mde-shell-egui.service` and is enabled into

## Packaging blockers and missing proof

1. The installed-seat proof is still missing. No clean target has demonstrated
   `systemd-creds encrypt/decrypt`, a real `mcnf-secret get`/`put`, creation of
   the root-only encrypted credential, generation of the public key, installation
   of the shell drop-in, `systemctl daemon-reload`, or successful loading of
   `$CREDENTIALS_DIRECTORY/music-action-private-key` by the root DRM shell.
   No installed `mde-musicd` has accepted a signed Music mutation with that
   generated public key, rejected a wrong-key/replay request, or completed a
   rotation proof.

2. The RPM's declared requirements include `age` and the ELF capability
   `libcurl.so.4`, but do not declare the command packages `openssl` or
   `curl`. The provisioning helper directly executes `/usr/bin/openssl`, and
   the shipped `/opt/mcnf/automation/secrets/mcnf-secret.sh` directly executes
   `/usr/bin/curl`. The audit host happens to provide both commands, but that
   is not proof that a minimal valid workstation installation will. This is a
   package-closure blocker for unattended provisioning unless the base image
   contract guarantees those command providers or a package gate proves them.
   `systemd-creds` is likewise exercised only on a host with systemd; this audit
   did not prove it in an extracted installed root.

3. The provisioning helper's self-test exercises synthetic seed validation,
   OpenSSL public-key derivation, static strings, and option presence only
   (`install-helpers/provision-music-action-credential.sh:33-50`). It does not
   exercise credential encryption, the mesh secret store, filesystem ownership
   and modes, the systemd drop-in merge, or daemon authorization. The two
   `mcnf-secret` self-tests are strong offline crypto/store fixtures, but they
   do not close the installed-seat gap.

Dell was not contacted or changed. The next required evidence is a controlled,
operator-approved workstation-seat install/provision/verify trace using the
current RPM, followed by authorized mutation and rotation checks; it must not
be inferred from the manifest or from the existing Dell runtime.
